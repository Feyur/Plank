# 🖥️ Локалка / Docker — как работать (для AI-агента и разработчика)

> ВАЖНО. Инфраструктура изменилась 2026-08-06. Прочитать перед работой с локальным окружением.

## Коротко
- **Docker с Mac УДАЛЁН намеренно** (жрал место/ОЗУ). На маке локалки больше НЕ поднимаются.
- **Локальная разработка (локалка) теперь на домашнем сервере** (headless Ubuntu, Docker).
- **Все важные данные и бэкапы ДУБЛИРУЮТСЯ на домашний сервер** — это резервная копия.

## Доступ к серверу
- `ssh homeserver` — по Wi-Fi (дома, сеть Yunet)
- `ssh hs` — по Tailscale (откуда угодно)
- Мониторинг сервера: http://localhost:8090 (Beszel, через SSH-туннель на маке)

## Где что лежит на сервере
- **Исходники проектов:** `~/projects/<категория>/<проект>/` (categories: clients / personal / experiments / tools / infra / archive). Это бэкап-копия, синхронизируется с маком.
- **Базы данных** — центральные Docker-контейнеры (сеть `localka-net`), данные перенесены с локалок мака:
  | Движок | Контейнер | Порт | Доступ |
  |---|---|---|---|
  | MySQL 8.4 | `localka-mysql` | 3306 | root / root |
  | MariaDB 10.6 | `localka-mariadb` | 3307 | root / root |
  | Postgres 16 | `localka-postgres` | 5432 | postgres / root |
  - Из контейнера проекта БД доступна по имени контейнера (`localka-mysql`, `localka-mariadb`, `localka-postgres`), если он в сети `localka-net`.

## Как поднять локалку (на сервере)
1. Быстро (Node/Vite или PHP): `localka <категория/проект> <порт>`
   пример: `localka clients/Atank 3000`
2. С базой данных: контейнер проекта подключить к сети `localka-net`, а в конфиге БД указать
   `host = localka-mysql` (или mariadb/postgres) вместо `localhost`.
   Пример (PHP-CMS): создать локальный конфиг с `host => 'localka-mysql'` и запустить php:8.3-apache в `localka-net`.
3. Доступ с мака: порты **3000–3003** и **8090** уже проброшены в SSH-туннель. Нужен другой порт —
   попросить ассистента добавить в туннель (`~/Library/LaunchAgents/com.feyur.homeserver-tunnel.plist`).

## Бэкапы и важные данные — правило
- **Бэкапы проекта хранятся на СЕРВЕРЕ, а не на маке.** Папки `backups/`, архивы, дампы — держать
  на домашнем сервере (`~/projects/<категория>/<проект>/`, дампы БД в `~/db-dumps/`). На маке их НЕ копим —
  только зря занимают место. Новый бэкап сразу класть/синхронизировать на сервер:
  `rsync -a ./backups/ homeserver:projects/<категория>/<проект>/backups/`
- **Базы данных НЕ лежат в файлах проекта.** Их бэкапят отдельно: `mysqldump` / `pg_dump` → файл → на сервер.
  При изменении данных в БД — снять дамп и положить на сервер (`~/db-dumps/`).
- **node_modules / vendor / build / dist** — в бэкап НЕ включаются (регенерируются `npm install` / `composer install`).
- Всё остальное важное (исходники, дампы, конфиги, доки) — **дублировать на домашний сервер**.

## Правила для AI-агента
1. **Не запускай Docker на маке** — его там нет. Локалки поднимай на сервере (`ssh homeserver` / `ssh hs`).
2. Нужна БД для проекта — она уже на сервере (см. таблицу выше) либо импортируй дамп в `localka-*`.
3. **Важные результаты, данные, дампы — сохраняй/дублируй на домашний сервер.**
4. Деплой этого проекта обычно идёт на **Timeweb** (сборка на локалке → выгрузка). Локалка = dev-среда.
